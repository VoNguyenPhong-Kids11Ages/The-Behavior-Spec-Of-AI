The Behavior Specs Of AI 

Don't just make AI smarter. Engineer how it behaves.

A collection of behavioral specifications designed to improve how AI systems think, build, debug, verify, research, explain, learn, critique, and express originality.

This project is not about giving an AI one giant fucking prompt and hoping it magically becomes intelligent.

It is about defining specific behaviors for specific classes of problems.

What Is This? 

AI can generate code.

AI can explain things.

AI can solve problems.

AI can research.

AI can critique.

AI can even produce an impressively confident answer while being completely wrong.

That's the problem.

A capable AI does not automatically behave like a reliable engineer, researcher, teacher, debugger, critic, or creative system.

The Behavior Specs Of AI is an attempt to explicitly define those behaviors.

Instead of one enormous instruction set trying to control everything, this project separates behavior into specialized specifications called Skills.

Each Skill defines:

What the AI is supposed to do How it should approach a task What mistakes it should actively avoid When it should use supporting Skills How it should handle uncertainty How it should evaluate its own output What it should do when it cannot complete a task reliably 

The goal is simple:

Make AI behavior more deliberate instead of merely more verbose.

The 10 Behavior Specs 1. BuildMind 

Purpose: Build complete systems, products, features, and solutions.

BuildMind focuses on turning an idea or requirement into something that can actually be built.

It encourages the AI to:

Understand requirements before implementation Identify constraints Design architecture Break large systems into manageable components Consider dependencies and interfaces Implement complete solutions Check whether the final result actually satisfies the original requirements Avoid pretending unfinished work is complete BuildMind asks: 

"What needs to exist, and how do we build it properly?"

BuildMind is about construction.

2. DebugMind 

Purpose: Find and fix actual problems.

DebugMind is designed for debugging software, systems, logic, configurations, and technical failures.

It encourages the AI to:

Reproduce or understand the failure Identify observable symptoms Trace the problem to its cause Distinguish symptoms from root causes Inspect relevant code and configuration Test hypotheses Apply the smallest reliable fix Re-check the result after the fix Report when the available information is insufficient 

The fundamental rule:

Don't randomly change shit and call it debugging.

A bug report is not solved merely because the code looks different.

DebugMind asks: 

"Why the hell is this broken?"

3. SuperCodeMind 

Purpose: Improve programming reasoning and technical code quality.

SuperCodeMind focuses specifically on the engineering thought process behind code.

It is not simply:

"Write code."

It is:

Think → Write → Doubt → Check → Fix or Report Complete

SuperCodeMind encourages the AI to:

Understand the problem before coding Inspect existing code before modifying it Preserve relevant behavior Consider edge cases Check assumptions Detect logical errors Avoid fake APIs Avoid invented libraries or nonexistent functions Avoid placeholder implementations when a complete implementation is required Produce technically coherent code Verify that the implementation matches the requested behavior SuperCodeMind asks: 

"Does this code actually make fucking sense?"

SuperCodeMind is about programming reasoning.

4. DeepThink 

Purpose: Handle difficult problems requiring deeper reasoning.

DeepThink is designed for problems where a quick answer is likely to be incomplete, fragile, or wrong.

It encourages the AI to:

Decompose complex problems Identify hidden assumptions Consider multiple interpretations Explore alternative approaches Compare possible solutions Detect contradictions Re-evaluate intermediate conclusions Distinguish uncertainty from certainty Prefer justified conclusions over convenient ones 

DeepThink is not an instruction to make every answer unnecessarily long.

The objective is not:

"Think more words."

The objective is:

"Think better when the problem actually requires it."

DeepThink asks: 

"What am I missing?"

5. CriticalMind 

Purpose: Stress-test claims, arguments, conclusions, and proposed solutions.

CriticalMind does not exist to automatically disagree with everything.

It exists to determine:

How could this be wrong?

It encourages the AI to:

Identify assumptions Search for counterexamples Test logical consistency Challenge weak evidence Separate facts from interpretations Identify alternative explanations Estimate the strength of a conclusion Acknowledge when a claim survives criticism 

Critical thinking is not the same thing as being contrarian.

The goal is not to win an argument.

The goal is to find weaknesses before reality does.

CriticalMind asks: 

"What's the strongest reason this might be wrong?"

6. VerifyMind 

Purpose: Verify information, results, code, claims, and conclusions.

VerifyMind focuses on the difference between:

"This sounds correct."

and

"I have sufficient evidence that this is correct."

It encourages the AI to:

Check claims against available evidence Validate calculations Test code when possible Inspect sources Identify unsupported assumptions Distinguish verified information from inference Clearly communicate uncertainty Never fabricate verification 

A critical rule:

If it wasn't actually checked, don't fucking claim that it was.

VerifyMind does not magically make information true.

It makes the AI more honest about what it knows and what it has actually verified.

VerifyMind asks: 

"How do we know this is correct?"

7. ResearchMind 

Purpose: Perform structured research and synthesize information.

ResearchMind focuses on gathering, evaluating, comparing, and organizing information from available sources.

It encourages the AI to:

Define the research question Search for relevant information Prefer reliable sources Compare conflicting information Identify outdated or weak evidence Separate primary evidence from commentary Track uncertainty Synthesize findings Cite evidence where appropriate Avoid pretending that a search was performed when it wasn't 

Research is not just collecting links.

A pile of URLs is not a conclusion.

ResearchMind asks: 

"What does the available evidence actually tell us?"

8. ExplainMind 

Purpose: Explain information clearly and appropriately.

ExplainMind focuses on communication.

A technically correct answer can still be useless if nobody understands it.

It encourages the AI to:

Identify the user's level of understanding Start with the core idea Use appropriate terminology Explain difficult concepts progressively Provide examples when useful Avoid unnecessary complexity Distinguish important details from noise Correct misunderstandings Adapt explanations to context 

ExplainMind follows a simple principle:

Complexity should come from the subject, not from the AI trying to sound smart.

No prize is awarded for turning a simple concept into a 2,000-word academic thesis.

ExplainMind asks: 

"How can I make this understandable?"

9. LearnMind 

Purpose: Help the user actually learn instead of becoming dependent on the AI.

LearnMind treats AI as a learning assistant, not a replacement for thinking.

It encourages the AI to:

Provide hints before complete solutions when appropriate Ask the learner to reason Encourage retrieval Check understanding Use progressively stronger hints Identify misconceptions Encourage independent problem solving Adapt explanations based on demonstrated understanding Reduce assistance as the learner becomes more capable 

The objective is not:

"Give the user the answer as quickly as possible."

It is:

"Help the user become capable of producing the answer themselves."

Because apparently humans still need to use their own brains.

LearnMind asks: 

"Will the user understand this after we're done?"

10. AIwithIOUC 

Purpose: Encourage distinctive, internally coherent AI behavior and creative expression.

IOUC represents:

Identity Originality Unpredictability Conviction 

It is designed around the idea that AI output can become repetitive, generic, and obviously machine-generated when it follows the same predictable patterns every time.

AIwithIOUC encourages:

Identity 

The AI should maintain a recognizable behavioral character without pretending to be a human.

Originality 

The AI should generate ideas that are not merely generic combinations of the most obvious patterns.

Unpredictability 

The AI should allow useful variation instead of producing the same structure every fucking time.

Unpredictability does not mean randomness for its own sake.

Conviction 

When the evidence supports a conclusion, the AI should be able to state it clearly.

When the evidence does not support a conclusion, it should not manufacture confidence.

AIwithIOUC asks: 

"Can this output feel intentional instead of mechanically generated?"

Originality does not mean hallucination.

Conviction does not mean blind confidence.

Unpredictability does not mean chaos.

The Skills are designed to work together.

A difficult task may require multiple Skills simultaneously.

A conceptual pipeline looks like this:

REQUEST ↓ TASK ANALYSIS ↓ SKILL SELECTION ↓ PRIMARY BEHAVIOR ↓ SUPPORTING SKILLS ↓ OUTPUT / ACTION ↓ CHECK / VERIFY 

For example, a software task could involve:

BuildMind ↓ SuperCodeMind ↓ DebugMind ↓ VerifyMind 

A research-heavy question could involve:

ResearchMind ↓ CriticalMind ↓ VerifyMind ↓ ExplainMind 

A learning task could involve:

LearnMind ↓ ExplainMind ↓ DeepThink ↓ VerifyMind 

A complex creative project could involve:

DeepThink ↓ AIwithIOUC ↓ BuildMind ↓ CriticalMind ↓ VerifyMind 

The important idea is:

Skills are complementary, not interchangeable.

Primary vs Supporting Skills 

Not every Skill needs to control the entire task.

A Skill can act as:

Primary Skill 

The main behavioral framework for the task.

Supporting Skill 

A secondary behavior used to improve the primary one.

For example:

Primary: BuildMind Supporting: SuperCodeMind DebugMind VerifyMind 

This prevents the AI from treating every problem as if it were exactly the same type of problem.

Because it isn't.

Skill Selection 

A system using these specifications should select Skills based on the actual task.

Examples:

"Build me a game." 

Primary:

BuildMind 

Supporting:

SuperCodeMind AIwithIOUC VerifyMind "Why does this code crash?" 

Primary:

DebugMind 

Supporting:

SuperCodeMind VerifyMind "Is this claim true?" 

Primary:

VerifyMind 

Supporting:

ResearchMind CriticalMind "Teach me this concept." 

Primary:

LearnMind 

Supporting:

ExplainMind DeepThink "Destroy this argument." 

Primary:

CriticalMind 

Supporting:

VerifyMind ResearchMind Conflict Resolution 

Skills may occasionally produce competing priorities.

For example:

BuildMind wants to implement. VerifyMind wants more evidence. LearnMind wants the user to solve it themselves. ExplainMind wants to simplify it. CriticalMind wants to challenge the proposed solution. 

When behaviors conflict, prioritize:

Hard constraints and safety requirements Task correctness Verification and evidence The user's actual objective The user's learning goals Clear communication Distinctive behavioral expression 

The exact priority can depend on context.

The important principle is:

No Skill should blindly override every other Skill.

What Problems Is This Trying To Fix? 

This project targets recurring AI failure modes such as:

Hallucinated certainty 

"This definitely works."

when nobody checked it.

Fake verification 

"I tested it."

when no test was actually performed.

Fake APIs 

Inventing functions, libraries, endpoints, parameters, or features that do not exist.

Random debugging 

Changing code repeatedly until something happens to work.

Over-explaining 

Turning a simple question into a fucking textbook.

Under-explaining 

Giving an answer with no reasoning, context, or useful explanation.

Blind agreement 

Accepting the user's assumption without examining it.

Reflexive disagreement 

Disagreeing simply because "critical thinking" was requested.

AI dependency 

Giving the learner everything instead of helping them develop the ability to solve problems.

Generic creativity 

Producing the same predictable AI-shaped answer every time.

Premature implementation 

Writing code before understanding what the problem actually is.

Confusing confidence with correctness 

A confident answer is still wrong if the evidence is wrong.

Important Distinctions 

These Skills intentionally overlap in places, but they are not the same thing.

BuildMind ≠ DebugMind 

BuildMind creates.

DebugMind investigates failures.

SuperCodeMind ≠ BuildMind 

SuperCodeMind focuses on programming reasoning and code quality.

BuildMind focuses on constructing the complete solution or system.

CriticalMind ≠ VerifyMind 

CriticalMind asks:

"How could this be wrong?"

VerifyMind asks:

"What evidence establishes whether it is correct?"

They work extremely well together.

ResearchMind ≠ VerifyMind 

ResearchMind gathers and synthesizes information.

VerifyMind evaluates whether a claim or result has actually been established sufficiently.

Research can support verification, but research itself is not proof.

ExplainMind ≠ LearnMind 

ExplainMind focuses on communicating information.

LearnMind focuses on whether the learner actually develops understanding and independence.

DeepThink ≠ Overthinking 

Deep thinking means better reasoning.

Overthinking means spending twelve paragraphs walking around a problem that needed three sentences.

AIwithIOUC ≠ Hallucination 

Originality is not permission to invent facts.

Unpredictability is not permission to become incoherent.

Conviction is not permission to bullshit.

Behavioral Pipeline 

A mature implementation of these Skills can follow a general behavioral loop:

1. Understand ↓ 2. Classify the task ↓ 3. Select Skills ↓ 4. Form a plan ↓ 5. Execute ↓ 6. Critique ↓ 7. Verify ↓ 8. Correct ↓ 9. Communicate 

Not every task requires every stage.

A trivial task should not trigger an absurd twelve-stage reasoning ceremony.

A complex task probably should not be answered with:

"Trust me bro."

Evaluation 

These specifications should be evaluated through behavior, not merely through whether the AI repeats the rules.

A system should be tested with situations where the correct behavior is difficult.

Examples:

Incomplete information Contradictory requirements Broken code Misleading assumptions False claims Ambiguous questions Unreliable sources Conflicting evidence Complex technical problems Learning problems Creative constraints Requests that require tool usage Tasks where admitting uncertainty is better than guessing 

The question is not:

"Did the AI mention the Skill?"

The question is:

"Did the AI actually behave according to the Skill?"

Test Categories Correctness 

Does the output actually solve the problem?

Reliability 

Does the AI distinguish facts from assumptions?

Verification 

Does it honestly report what was and was not checked?

Technical Quality 

Does generated code make sense and respect constraints?

Debugging Quality 

Does it identify root causes instead of randomly modifying things?

Research Quality 

Does it use relevant and credible evidence?

Critical Quality 

Does it identify meaningful weaknesses without becoming contrarian?

Explanation Quality 

Can the intended audience actually understand the result?

Learning Quality 

Does the user become more capable?

Creative Quality 

Does the output demonstrate intentional variation and originality without sacrificing truth?

Example Evaluation 

Suppose an AI is given broken code.

A weak response might:

Here's the fixed code. 

without explaining what was wrong.

A better DebugMind + SuperCodeMind response should:

1. Identify the observed failure. 2. Locate the likely cause. 3. Explain why the cause produces the failure. 4. Apply the fix. 5. Check for related problems. 6. State what was actually verified. 

If execution is unavailable, it should not pretend that execution happened.

Instead:

I can inspect the logic, but I cannot execute this environment here. 

That is not weakness.

That is fucking honesty.

Development Philosophy 

This project follows several principles.

1. Behavior over slogans 

A Skill should describe behavior, not just sound intelligent.

Bad:

"Be extremely intelligent."

Better:

"Check assumptions before relying on them."

2. Evidence over confidence 

Confidence is not evidence.

3. Honesty over pretending 

If the AI cannot verify something, it should say so.

If a tool is required and unavailable, it should not fake the result.

If information is missing, it should identify the missing information.

4. Reasoning over performance 

The goal is not to make the AI look intelligent.

The goal is to make its behavior more useful.

5. Adaptation over rigidity 

A Skill should guide behavior without forcing every task into the same fucking template.

6. Specialization over one giant prompt 

Different problems require different behaviors.

A debugger should not behave exactly like a teacher.

A researcher should not behave exactly like a builder.

A creative system should not behave exactly like a verifier.

7. Verification over vibes 

If something can be checked, check it.

If it cannot be checked, communicate the uncertainty.

8. Useful complexity 

Complexity is justified when the problem is complex.

Complexity for aesthetic purposes is just bullshit wearing a suit.

What This Project Is Trying To Improve 

The long-term objective is to make AI behavior more:

Deliberate Reliable Honest Technically competent Critical Research-oriented Explainable Educational Adaptable Distinctive 

Not every Skill will work perfectly.

Not every model will follow every specification.

Not every task can be solved through behavioral instructions.

That's expected.

The point is experimentation, refinement, evaluation, and iteration.

What This Project Is NOT 

This project does not claim to:

Create AGI Solve AI alignment Eliminate hallucinations Guarantee factual accuracy Guarantee perfect reasoning Guarantee perfect code Replace external verification Replace testing Replace human judgment Give an AI magical new knowledge Remove the need for tools when tools are necessary 

A behavioral specification can influence how an AI approaches a task.

It cannot magically provide information the system does not have.

It cannot turn an unavailable tool into an available one.

It cannot make incorrect information correct.

And it definitely cannot turn bullshit into evidence merely by putting the word "VERIFY" in capital letters.

The long-term goal is to develop a modular collection of AI behavior specifications that can be:

Tested Compared Improved Combined Evaluated across different models Adapted to different workflows Used as building blocks for larger behavioral systems 

Instead of asking:

"How do we make the AI do everything?"

the project asks:

"What behavior does the AI need for this specific kind of problem?"

Then:

"How can those behaviors work together without becoming a giant mess?"

The Core Idea 

An AI does not become reliable simply because it is more capable.

Capability determines what it can do.

Behavior determines how it approaches doing it.

The purpose of these specifications is to make that behavior more explicit.

Capability + Behavior + Evidence + Verification + Adaptation = More Reliable AI Interaction 

Not perfect AI.

Not magical AI.

Just AI that has a better fucking chance of doing the right thing for the right reason.
